\section{¿Qué es Emacs?}
\label{sec:orgaf099d7}
\begin{frame}[allowframebreaks]{Un entorno de programación extensible y personalizable}
\begin{itemize}
\item No es simplemente un editor de texto.
\item Es un \alert{intérprete de Lisp} diseñado para la computación interactiva.
\item Un entorno de trabajo que evoluciona contigo.
\item "El sistema operativo dentro de tu sistema operativo".
\item Filosofía: Proveer un entorno autocontenido y altamente adaptable
para la manipulación de texto y datos estructurados.
\end{itemize}
\end{frame}

\begin{frame}[allowframebreaks]{Filosofía: Plataforma vs. Producto}
\begin{itemize}
\item \alert{\alert{VS Code:}} Un producto con decisiones predefinidas por terceros.
\item \alert{\alert{Emacs:}} Una plataforma donde tú escribes el comportamiento del software.
\item \alert{\alert{Inversión:}} Tu configuración evoluciona contigo por décadas; no caduca.
\item \alert{\alert{Contexto único:}} "Everything in Emacs" para reducir el cambio de
aplicaciones.
\end{itemize}

Es un ecosistema que puede ser personalizado a tu estilo de trabajo,
con el principio \emph{Everything in Emacs} que reduce la necesidad de
cambiar de contexto entre aplicaciones.
\end{frame}

\begin{frame}[allowframebreaks]{El Corazón: Elisp (Emacs Lisp)}
\begin{itemize}
\item Casi todo lo que ves en Emacs está escrito en Elisp.
\item Puedes evaluar código en tiempo real.
\item No necesitas reiniciar el editor para aplicar cambios profundos.
\item \alert{Ejemplo:} ¿Quieres que el editor se comporte distinto al guardar un archivo? Escribe una función y conéctala a un "hook".
\end{itemize}
\end{frame}

\begin{frame}[fragile,allowframebreaks]{Conceptos Clave de Operación}
 \begin{itemize}
\item \alert{\alert{Búferes y Ventanas:}} La unidad de trabajo es el búfer (archivo, proceso, ayuda).
\item \alert{\alert{Modalidad sin modos estrictos:}} Operación directa complementada con "modos menores".
\item \alert{\alert{Comandos por teclado:}} Uso intensivo de \texttt{M-x} y \texttt{C-x} para ejecutar funciones Elisp.
\item \alert{\alert{Documentación integrada:}} Ayuda instantánea con \texttt{C-h k} (teclas) y \texttt{C-h f} (funciones).
\end{itemize}
\end{frame}

\begin{frame}[fragile,allowframebreaks]{Emacs en el contexto académico y de desarrollo}
 \begin{itemize}
\item \alert{\alert{Redacción técnica:}} Modo \alert{Org} e Integración con \LaTeX y BibTeX (RefTeX).
\item \alert{\alert{Software Libre:}} Garantiza libertad de uso, estudio y
modificación (GNU GPL).
\item \alert{\alert{Gestión bibliográfica:}} Herramientas como \texttt{org-ref} para investigadores.
\item Soporte nativo para decenas de lenguajes de programación.
\end{itemize}
\end{frame}

\begin{frame}[fragile,allowframebreaks]{La Joya de la Corona: Org-mode}
 \begin{itemize}
\item Mucho más que "tomar notas": un ecosistema de productividad completo.
\item \alert{\alert{Gestión:}} Tareas (GTD), agendas y calendarios (\texttt{org-agenda}).
\item \alert{\alert{Exportación:}} Genera PDFs, HTML y diapositivas (como esta) desde un solo origen.
\item \alert{\alert{Literate Programming:}} Documentos que mezclan texto, ecuaciones y código ejecutable.
\end{itemize}
\end{frame}

\begin{frame}[allowframebreaks]{¿Qué más puede hacer Emacs?}
\begin{itemize}
\item \emph{Edición de código}: Completado inteligente (company-mode),
verificación de sintaxis (flycheck), navegación (lsp-mode).
\item \emph{Gestión de proyectos} (projectile, magit).
\item \emph{Composición de documentos} (Org mode, AUCTeX).
\item \emph{Correo y noticias} (mu4e, gnus).
\item \emph{Agenda y calendario} (org-agenda).
\item \emph{Shell integrada} (eshell, term, vterm).
\item \emph{Navegación web} (eww).
\item \emph{Personalización total}: Desde atajos de teclado hasta la
creación de nuevas aplicaciones dentro de Emacs.
\end{itemize}
\end{frame}

\begin{frame}[allowframebreaks]{Conclusión: ¿Qué es Emacs?}
\begin{itemize}
\item Emacs no es solo un editor;
\item Su curva de aprendizaje es pronunciada, pero su retorno en
productividad y control es enorme.
\item \alert{\alert{VS Code:}} Gratificación instantánea, pero techo de personalización bajo.
\item \alert{\alert{Emacs:}} Frustración inicial, pero techo de personalización infinito.
\item Se trata de disfrutar el proceso de "construir tu propia herramienta".
\item Si buscas una herramienta que simplemente funcione de salida, quédate en VS Code.
\item Si buscas una herramienta que sea una \alert{\alert{extensión de tu
pensamiento}} y estás dispuesto a aprender, Emacs es el destino
final.
\end{itemize}
\end{frame}

\section{Configuración e Instalación en Windows}
\label{sec:org1215567}
\begin{frame}[fragile,allowframebreaks]{Procedimiento de Configuración en Windows}
 \label{org3f7c0a5}

Se requiere realizar los siguientes ajustes para que Emacs opere:

\begin{enumerate}
\item Instalar WSL o un distro de Linux: Se pueden seguir los pasos de la
\href{https://learn.microsoft.com/es-es/windows/wsl/install}{Guía de Instalación}
\item Instalar Emacs:
\begin{verbatim}
        sudo apt-get update
        sudo apt install emacs
\end{verbatim}
\item Instalar \LaTeX{} (básica o completa):
\begin{verbatim}
	sudo apt install texlive-full
\end{verbatim}
Existen otras opciones para Latex que consumen menos recursos (ver
\href{https://linuxconfig.org/how-to-install-latex-on-ubuntu-20-04-focal-fossa-linux}{enlace}):
\begin{verbatim}
        sudo apt install texlive-latex-extra
\end{verbatim}
\end{enumerate}
\end{frame}

\begin{verbatim}
sudo apt-get install texlive-xetex
\end{verbatim}

\begin{verbatim}

\end{verbatim}

\begin{verbatim}

\end{verbatim}

\begin{verbatim}

\end{verbatim}

\item Configurar el archivo en \textasciitilde{}/.emacs.d/init.el
\end{enumerate}
\end{frame}

\begin{frame}[fragile,allowframebreaks]{Trouble Shooting Mamba Activate}
 Puede suceder que al ejecutar el comando \texttt{mamba activate} se presente el siguiente error
\begin{verbatim}
  'mamba' is running as a subprocess and can't modify the parent shell.
Thus you must initialize your shell before using activate and deactivate.

To initialize the current bash shell, run:
    $ eval "$(mamba shell hook --shell bash)"
and then activate or deactivate with:
    $ mamba activate
To automatically initialize all future (bash) shells, run:
    $ mamba shell init --shell bash --root-prefix=~/.local/share/mamba
If your shell was already initialized, reinitialize your shell with:
    $ mamba shell reinit --shell bash
Otherwise, this may be an issue. In the meantime you can run commands. See:
    $ mamba run --help

Supported shells are {bash, zsh, csh, posix, xonsh, cmd.exe, powershell, fish, nu}.
critical libmamba Shell not initialized
\end{verbatim}

En este caso se sugiere ejecutar el siguiente comando para poder usar
el comando. Sin embargo, la dirección debe coincidir con la dirección
en donde está instalado el \texttt{miniforge}. Para saber en donde está
instalado el miniforge ejecute:
\begin{verbatim}
conda env list
\end{verbatim}

\begin{verbatim}

# conda environments:
#
# * -> active
# + -> frozen

pyt-eqa-fge              /home/leningfe/miniforge3/envs/pyt-eqa-fge
pyt-ml                   /home/leningfe/miniforge3/envs/pyt-ml
tfmlenv              *   /home/leningfe/miniforge3/envs/tfmlenv
whatsapp-osint           /home/leningfe/miniforge3/envs/whatsapp-osint

\end{verbatim}

Para mi caso la dirección es \texttt{/home/leningfe/miniforge3}. Que también
puede escribirse como \texttt{\textasciitilde{}/miniforge3}. En consecuencia, desde el
terminal ejecute:
\begin{verbatim}
  mamba shell init --shell bash --root-prefix=~/miniforge3
\end{verbatim}

Una vez ejecutado reinicie el shell o ejecute \texttt{source
\textasciitilde{}/.bashrc}. Puede reiniciar saliendo de wsl con \texttt{exit} y luego \texttt{wsl
-{}-{}shutdown}, si se abrió sesión de wsl desde un CMD de Windows

\begin{frame}[fragile,allowframebreaks]{Configuración Emacs}
 \label{org454b557}

\begin{itemize}
\item El archivo init.el puede generar instalaciones y activaciones para
emacs por lo que se sugiere reiniciar emacs para que las
configuraciones surtan efecto
\item El comportamiento de Emacs es completamente configurable por el
usuario a través del archivo \textasciitilde{}/.emacs.d/init.el
\item El directorio \texttt{/.emacs.d/} se genera la primera vez que abre
emacs. Debe crear el archivo \texttt{init.el} dentro de éste.
\item Para que no exista conflictos en el uso de la configuración revise
si existe alternativamente el archivo oculto \texttt{.emacs} en la raíz del
sistema operativo. Para esto use el comando \texttt{ls -lha} desde la
posición de \texttt{home}. Por ejemplo, debe existir únicamente el
directorio \texttt{.emacs.d}:
\end{itemize}

\begin{verbatim}
cd
pwd
ls -lha | grep emacs
\end{verbatim}

\begin{itemize}
\item Si existe el archivo \texttt{.emacs} borrarlo con \texttt{rm .emacs} desde la
posición de  home
\end{itemize}
\end{frame}

 \begin{enumerate}

     rm .emacs

\begin{verbatim}

\end{enumerate}

\section{Comandos básicos de Emacs}
\label{sec:org0554ccf}
\begin{frame}[fragile,allowframebreaks]{Comandos básicos de Emacs}
 Emacs utiliza las teclas \texttt{CTRL} y \texttt{ALT}, en combinación con otras para
desencadenar acciones y comportamientos. Abreviamos \texttt{CTRL} con \texttt{C} y
\texttt{ALT}, que se conoce como \texttt{META}, con la letra \texttt{M}.

Se sugiere que revise el Tutorial Integrado en Emacs para
familiarizarse con el sistema. Este tutorial está disponible en
español ejecutando el comando \texttt{M-x help-with-tutorial-spec-language}.

Para ejecutar un comando compuesto no es necesario mantener presionada
la combinación de teclas. Usted notará en la barra inferior que cuando
ha presionado una combinación, Emacs responde indicando el comando y
aguardando a que complete si es que el comando requiere de
adicionales. Caso contrario se ejecuta.


\begin{center}
\begin{tabular}{|l|l|l|l|}
\hline
Comando & Acción & Comando & Acción \\
\hline
C-x C-s & guardar & C-x C-c & Salir Emacs \\
\hline
C-n & siguiente renglón & C-p & anterior renglón \\
\hline
C-f & avanza un carácter & C-b & atrás un carácter \\
\hline
M-f & avanza una palabra & M-b & atrás una palabra \\
\hline
C-a & ir a inicio & C-e & ir al fin \\
\hline
C-SPC & selecciona región & C-g & cancelar comando \\
\hline
C-d & Borrar un carácter & M-d & borrar palabra \\
\hline
\end{tabular}
\end{center}

\texttt{path} a la carpeta de entornos de \alert{Anaconda}. Para ser cuál es la

\end{itemize}

\section{Integración de IA en Emacs GPTEL}
\label{sec:orgd47657e}
\begin{frame}[fragile,allowframebreaks]{Habilitación de Modelos Grandes de Lenguaje o LLM}
 \begin{enumerate}
\item Disponer de una cuenta en GitHub. La configuración del archivo
\texttt{init.el} hace uso por defecto de \texttt{CoPilot}
\item Instalar \texttt{wslview} a fin de que en el primer uso del Chat se pueda
habilitar el uso de \texttt{CoPilot} en el dispositivo: \texttt{sudo apt install wslu}
\item Instalar el paquete para modo de MarkDown. Los archivos de chat con
las \texttt{LLM} se guardan por defecto en formato \texttt{MarkDown}. Sin
embargo, si existiera problema, se pueden modificar para que se
guarden en archivo \texttt{.org}. Para esto puede ejecutar:
\begin{enumerate}
\item \texttt{M-x package-install RET}
\item busca el paquete \texttt{markdown-mode}
\end{enumerate}
\end{enumerate}
\end{frame}
\begin{frame}[fragile,allowframebreaks]{Utilización de Modelos Grandes de Lenguaje o LLM}
 El paquete que realiza la conexión entre \texttt{Emacs} y los diferentes
\texttt{LLMs} es \texttt{GPTEL}. Para iniciar un chat y configurarlo puede ejecutar:
\texttt{M-x gptel-menu}. Se abrirá un menú en donde podrá configurar el
funcionamiento del sistema, cambiar de \texttt{LLM} y configurar desde donde
se envía el prompt y dónde se obtiene la respuesta.

Una sesión de chat se puede grabar \texttt{C-x C-s} y se puede restablecer
abriendo el archivo y activando \texttt{M-x gptel-mode}.
\end{frame}

\section{Configuración e Instalación en MacOS}
\label{sec:org51c5e2c}
\begin{frame}[fragile,allowframebreaks]{Configuración en MacOS (Instalar Brew)}
 \begin{enumerate}
\item \alert{Instalar \texttt{brew}:}
\begin{itemize}
\item Utilizar el comando de la página de HomeBrew
\item El comando identifica la arquitectura del sistema automáticamente
\item Seguir las indicaciones en pantalla
\end{itemize}
\end{enumerate}

\begin{verbatim}
 /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

\section{Funciones avanzadas de WSL}
\label{sec:org3b917ca}

\begin{frame}[label={sec:org622dc5f}]{Funciones avanzadas de WSL}
El uso de espacio de por parte de WSL cambia
dinámicamente. Especialmente, en proyectos de \emph{machine learning}. Para
mitigar esta opción hay las siguientes opciones:

\begin{enumerate}
\item Mover el distro de WSL a otra unidad de disco
\item Comprimir el espacio que ocupa el distro en el disco
\item Eliminar el distro
\end{enumerate}
\end{frame}

\begin{frame}[fragile,allowframebreaks]{Mover el distro de WSL}
 Desde un prompt de Windows realice las siguientes operaciones desde un Powershell
\begin{enumerate}
\item Exportar el distro a otra unidad de disco
\begin{verbatim}
   wsl --export Ubuntu-22.04 D:\WSL\ubuntu22.tar
\end{verbatim}
\item Desinstalar el distro de la unidad \texttt{C:} (Windows)
\begin{verbatim}
   wsl --unregister Ubuntu-22.04
\end{verbatim}
\item Importar de nuevo desde la nueva unidad \texttt{D:}
\begin{verbatim}
   wsl --import Ubuntu-22.04 D:\WSL\Ubuntu22 D:\WSL\ubuntu22.tar --version 2
\end{verbatim}
\end{enumerate}
\end{frame}
\begin{frame}[fragile,allowframebreaks]{Comprimir/Respaldar un distro de WSL}
 \label{org4afddf5}
Realice las siguientes operaciones desde un Powershell
\begin{enumerate}
\item Terminar WSL completamente
\begin{verbatim}
   wsl --shutdown
\end{verbatim}
\item Abrir \texttt{diskpart} en un Powershell
\begin{verbatim}
   diskpart
\end{verbatim}
\item Seleccionar el archivo virtual que contiene el distro. Para esto
debe ubicar la ruta al archivo ext4.vhdx del distro
\begin{verbatim}
    select vdisk file="C:\Users\<YourUser>\AppData\Local\Packages\CanonicalGroupLimited...Ubuntu22.04...\LocalState\ext4.vhdx"
    compact vdisk
\end{verbatim}
\end{enumerate}
\end{frame}
\begin{frame}[label={sec:org8947e26},fragile]{Eliminar el Distro}
 Para eliminar el distro sólo ejecutamos desde un Powershell:
\begin{verbatim}
wsl --unregister <Nombre Distro>
\end{verbatim}

Para esto, el distro debe estar detenido y su nombre localizado. Esto
último lo puede derivar con el comando \texttt{wsl -l -v} desde Powershell
\end{frame}
\begin{frame}[fragile,allowframebreaks]{Actualizar el Distro a una versión nueva: requisitos y respaldo}
 El siguiente procedimiento debe hacerse con cuidado y con un respaldo
de la información ya que puede conllevar la pérdida de datos si no
finaliza con éxito.

El objetivo es actualizar el distro de una version LTS inferior a una
superior (e.g. 22.04 a 24.04).

\begin{enumerate}
\item Antes de comenzar, realizar el procedimiento de
\hyperlink{org4afddf5}{respaldo de la distribución WSL}.

\item En PowerShell de Windows, consultar las distribuciones:

\begin{verbatim}
   wsl --list --verbose
\end{verbatim}

\begin{itemize}
\item Identificar el nombre exacto de la distribución.
\item La columna \texttt{VERSION} debe mostrar \texttt{2}.
\item Si muestra \texttt{1}, detener este procedimiento: primero se debe
convertir la distribución a WSL 2.
\end{itemize}

\item Abrir la terminal de Ubuntu y comprobar su versión:

\begin{verbatim}
   cat /etc/os-release
\end{verbatim}

Para este procedimiento debe indicar \texttt{VERSION\_ID}"22.04"\texttt{.
   Si ya indica =24.04}, no es necesario realizar esta actualización.
\end{enumerate}
\end{frame}

\begin{frame}[fragile,allowframebreaks]{Actualización de Ubuntu: comprobar systemd}
 \texttt{systemd} es el administrador de servicios de Linux. Debe estar
habilitado para seguir el procedimiento de actualización de Ubuntu
en WSL.

\begin{enumerate}
\item Dentro de Ubuntu, ejecutar:

\begin{verbatim}
   ps -p 1 -o comm=
\end{verbatim}

\item Interpretar el resultado:
\begin{itemize}
\item Si devuelve \texttt{systemd}, omitir el apartado de habilitación y
continuar con la actualización.
\item Si devuelve otro nombre, seguir el apartado siguiente.
\end{itemize}
\end{enumerate}
\end{frame}

\begin{frame}[fragile,allowframebreaks]{Actualización de Ubuntu: habilitar systemd si es necesario}
 Realizar este apartado solamente si la comprobación anterior no
devolvió \texttt{systemd}.

\begin{enumerate}
\item En PowerShell, comprobar la versión del programa WSL:

\begin{verbatim}
   wsl --version
\end{verbatim}

El soporte de systemd requiere WSL 0.67.6 o posterior.
Esta versión del programa no es lo mismo que la columna
\texttt{VERSION} de \texttt{wsl -{}-{}list -{}-{}verbose}.

Si WSL es anterior o no reconoce el comando, actualizarlo:

\begin{verbatim}
   wsl --update
\end{verbatim}

\item Dentro de Ubuntu, abrir su archivo de configuración:

\begin{verbatim}
   sudo nano /etc/wsl.conf
\end{verbatim}

\item Añadir lo siguiente, conservando las demás configuraciones:

\begin{verbatim}
   [boot]
   systemd=true
\end{verbatim}

Si ya existe la sección \texttt{[boot]}, añadir o modificar
\texttt{systemd=true} dentro de ella; no duplicar la sección.

\item Guardar y cerrar Nano: \texttt{Ctrl+O}, \texttt{Enter} y \texttt{Ctrl+X}.

\item Guardar cualquier trabajo abierto en otras distribuciones WSL.
En PowerShell, detener WSL:

\begin{verbatim}
   wsl --shutdown
\end{verbatim}

Este comando detiene todas las distribuciones WSL en ejecución.

\item Volver a abrir Ubuntu y comprobar:

\begin{verbatim}
   ps -p 1 -o comm=
\end{verbatim}

Debe devolver \texttt{systemd}. Si no lo hace, no continuar con la
actualización hasta resolver este requisito.
\end{enumerate}
\end{frame}

\begin{frame}[fragile,allowframebreaks]{Actualización de Ubuntu: ejecutar y verificar}
 \begin{enumerate}
\item Dentro de Ubuntu, actualizar los paquetes de la versión actual:

\begin{verbatim}
   sudo apt update && sudo apt full-upgrade -y
\end{verbatim}

Esperar a que termine correctamente. Si presenta errores,
resolverlos antes de continuar.

\item Iniciar la actualización de versión:

\begin{verbatim}
   sudo do-release-upgrade
\end{verbatim}

Confirmar que el destino propuesto sea Ubuntu 24.04 y seguir
las instrucciones. No interrumpir el proceso.

\item Al finalizar, seguir las instrucciones de reinicio del
actualizador. Si es necesario reiniciar la instancia desde
PowerShell, usar:

\begin{verbatim}
   wsl --terminate "NOMBRE_DE_LA_DISTRIBUCION"
\end{verbatim}

Sustituir \texttt{NOMBRE\_DE\_LA\_DISTRIBUCION} por el nombre obtenido
con \texttt{wsl -{}-{}list -{}-{}verbose}. Después, volver a abrir Ubuntu.

\item Verificar el resultado dentro de Ubuntu:

\begin{verbatim}
   cat /etc/os-release
   ps -p 1 -o comm=
\end{verbatim}

Los resultados esperados son:
\begin{itemize}
\item \texttt{VERSION\_ID}"24.04"=.
\item \texttt{systemd} como proceso principal.
\end{itemize}

El nombre registrado de la distribución en WSL puede seguir
siendo el anterior; comprobar la versión con \texttt{os-release}.

\item Probar las herramientas habituales: Emacs, exportación de
documentos Org a PDF y los entornos de Python.
\end{enumerate}

\begin{block}{Documentación}
\begin{itemize}
\item \href{https://ubuntu.com/wsl/docs/stable/howto/upgrade-ubuntu/}{Ubuntu: actualizar Ubuntu en WSL}
\item \href{https://learn.microsoft.com/en-us/windows/wsl/systemd}{Microsoft: habilitar systemd en WSL}
\end{itemize}
\end{block}
\end{frame}

\section{Funciones avanzadas de Anaconda}
\label{sec:org73ebe5a}
Los entornos de anaconda crecen con la instalación de paquetes y
librerías. A fin de evitar descargar nuevamente de internet, anaconda
almacena las descargas en el disco. Esto ocupa demasiado espacio, por
lo que es recomendable limpiar el cache, los logs y paquetes no
usados.
\begin{frame}[label={sec:org9a68bb4},fragile]{Comandos de Limpieza para Conda}
 Ejecute el siguiente comando para eliminar \texttt{tarballs}, limpiar el
cache, logs y paquetes no usados.
\begin{columns}
\begin{column}{0.4\columnwidth}
\begin{verbatim}
conda clean --all --yes
\end{verbatim}
\end{column}

\begin{center}

\end{center}
\end{column}
\end{columns}
\end{frame}
\begin{frame}[label={sec:org69436cc},fragile]{Eliminar un entorno de Conda}
 Para eliminar el entorno es necesario primero salir de él con el
comando \texttt{conda deactivate}. Una vez que esta desactivado:
\begin{verbatim}
conda deactivate
conda remove --name myenv --all
\end{verbatim}
Reemplace \texttt{myenv} con el nombre del entorno. Esto borrará toda la
información del entorno.
\end{frame}
\begin{frame}[label={sec:org8f080ce},fragile]{Crear un backup del entorno}
 Para replicar resultados es importante trabajar con los mismos
paquetes (incluyendo las versiones específicas de los mismos). Esto se
puede lograr exportando a un archivo \texttt{YAML}:
\begin{verbatim}
conda activate myenv
conda env export > myenv.yml
\end{verbatim}

Note que las versiones de los paquetes cambian con el sistema
operativo por lo que si el proyecto trabaja en un S.O. Windows, las
versiones no serán las mismas que se instalan en un S.O. Linux. Una
alternativa para evitar este problema y garantizar replicación es
trabajar con \texttt{Docker}.

Verifique que el archivo contenga tanto los paquetes de \texttt{pip} como los
de \texttt{anaconda}. 
\end{frame}
\begin{frame}[label={sec:orgbc837b1},fragile]{Crear un entorno desde YAML}
 \begin{verbatim}
conda env create -f myenv.yml
\end{verbatim}
Para verificar los paquetes instalados o restituidos use
\begin{verbatim}
conda list
\end{verbatim}
\end{frame}
\begin{frame}[fragile,allowframebreaks]{Entorno Anaconda Portable}
 El entorno se puede exportar como archivo portable para moverlo a otro
sistema operativo (de igual naturaleza) con:
\begin{verbatim}
conda pack -n myenv -o myenv.tar.gz
\end{verbatim}
Para restituirlo:
\begin{verbatim}
mkdir -p ~/envs/myenv
tar -xzf myenv.tar.gz -C ~/envs/myenv
source ~/envs/myenv/bin/activate
\end{verbatim}
\alert{\alert{Importante}} debe estar instalado en el entorno el paquete \texttt{conda
  pack}. Se puede instalar de las siguientes maneras:
\begin{verbatim}
    conda install -c conda-forge conda-pack
    mamba install conda-pack
    pip install conda-pack
\end{verbatim}
\end{frame}
